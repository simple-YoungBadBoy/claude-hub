## 2026-11-25 · 点 × 关不掉会话

**需求原话**：对话点击删除并不能删。要求能删除同时能退出对话页的 tmux，别再占用服务器的内存。

**原因**：关闭按钮用的是浏览器自带的 `confirm()`。Mac App 的 webview 不弹这个框，直接当成「取消」，所以删除请求根本没发出去（日志里也查不到 DELETE）。服务器这边关闭是正常的：tmux 会话结束后，Claude 进程会跟着退出。Mac App 里 `/clear` 的确认也是同一个问题。

**做法**：不再用系统弹框。第一次点 × 变成红色的「确认关闭」，4 秒内再点一次才真的关闭；`/clear` 也一样，要点两下。手机上 × 一直半透明显示，因为没有悬停。只改 web，不用重装 App。

**结论**：bug 修复，直接做。

## 2026-11-25 · 速度和报错：日志看不到错误、hook 多时卡

**需求原话**：/code-review 主要是速度和报错问题。看下日志的报错。（审查后用户回复「要」，按建议顺序修）

**价值**：出错时日志里能直接看到原因；Claude 忙的时候界面、状态和通知不再变慢或出错。

**成本/风险**：只改 server 和 web，不动 Mac App，也不影响安全模型，不加依赖。属于 bug 修复，直接做。

**做法**：
- 日志：接口出错时记下错误原因；访问日志加上状态码和耗时，不再记 `/api/hook`，GET 请求只记失败的和超过 2 秒的。
- 轮询：hook 事件不再各自起一轮 tmux 轮询，改成合并请求，一阵 hook 只跑一轮；所有轮询串行执行，旧结果不会覆盖新的。
- 锁：截屏、解析对话记录都放在锁外做，会话列表、对话、git 接口和 hook 处理不用再排队。
- 对话面板：带版本号刷新，对话记录没变时不重读也不重传；刷新失败时保留已显示的对话，只在顶部提示。
- 上传图片加 60 秒超时；事件推送跟不上的客户端会被断开，让它重连拿完整状态；终端和事件 websocket 写数据加超时，断网的连接会被清掉。

**结论**：做。

## 2026-11-24 · 加一个麻将：四川血战到底

**需求原话**：然后可以选择比如说玩一下打麻将啊什么的。

**价值**：等 Claude 干活的时候，除了德州还能打麻将。国内用户更熟悉麻将，手机上一局一两分钟，正好适合碎片时间。

**规则选择**：问过用户，选了四川血战到底（Claude 推荐的）。在四种规则里它最简单，机器人好写。具体是：
- 108 张牌（万、条、筒），开局定缺，缺的那门要先打完。
- 能碰、能杠，不能吃。可以点炮胡，也可以自摸；一炮多响也算。
- 有人胡了就退出，其余人接着打，直到三家胡牌或者牌摸完。
- 番型：对对胡 1 番，清一色 2 番，七对 2 番，龙七对，每个根 1 番，自摸 1 番，杠上开花 1 番，封顶 4 番，底分 10。
- 杠牌当场收钱：直杠由放杠的人付 20，暗杠每家付 20，补杠每家付 10。
- 流局时查花猪（付封顶）、查大叫（按听牌的最大番付）。
- 没做的：换三张、抢杠胡、过胡不胡、退税。

**筹码**：和德州、宠物共用一份筹码。开一局先从德州筹码里押 500（不够就押全部），一局最多输这 500，打完再结算回去。这样麻将不用改德州的筹码逻辑；代价是德州打到一半时不能开麻将，和宠物商店的规则一样。

**做法**：
- 新增 `server/internal/mahjong`，包括牌型、番数、机器人和牌局流程，结构照搬德州：机器人用 seq 防止过期的回合，打完一局存一次档（`mahjong.json`）。
- 前端加一个 🀄 麻将标签页：点一下抬起牌，再点一下打出，防止误触。音效复用德州那一套，加了打牌的「嗒」声，碰、杠、胡用语音念出来（`speechSynthesis`，设备上没有中文语音就只有合成音效）。
- e2e 用 `-mahjong-bot-ms` 让机器人出牌变快，打完一整局。

**成本与风险**：
- 新增一个 Go 包、一个前端组件，加几个接口：`/api/mahjong/start`、`/api/mahjong/act`，都走现有的鉴权和 `X-Hub` 校验，不涉及安全模型。
- 不加依赖，也不用重装 Mac App。
- 手机底栏多了一个标签，共 7 个，已经截图确认放得下。

**结论**：做。

## 2026-11-23 · 竞品第四轮（三轮优化）：接着以前的对话 / 分叉、分支提交、服务器负载

**需求原话**：继续去看一下其他竞品，然后有选择地进行优化，做三轮。

**调研**（agentboard、Codeman、HAPI、Happy、CloudCLI、VibeTunnel、Kanna、官方 Remote Control）后的取舍：

| 功能 | 来源 | 结论 |
|---|---|---|
| 新建会话时列出这个目录以前的对话，选一个接着聊（`--resume`），或分叉成新对话（`--fork-session`） | agentboard、Codeman、官方 | **第 1 轮做**。服务器重启、会话关掉后，现在只能接「最后一次」；以前的对话找不回来 |
| 「改动」页显示当前分支还没推送的提交、相对默认分支的提交，能看每个提交的 diff | 官方、Codeman | **第 2 轮做**。现在只能看没提交的改动，Claude 已经提交的看不到 |
| 显示服务器 CPU / 内存 / 每个 Claude 占的内存 | Codeman | **第 3 轮做**。服务器只有 4G，曾被跑死，开多个会话前要能看到余量 |
| 移动端快捷键条、/clear 二次确认 | agentboard、Codeman | 已经有了 |
| plan 模式审批、多选问题卡片 | Kanna、官方 | 现有读屏卡片解析的是通用编号选项，已覆盖 |
| 多终端平铺、子代理面板、产物画廊、会话置顶拖拽 | Codeman、agentboard | 以后再说：成本中等，或内存压力大 |
| 语音助手、多人协作、其他 agent | HAPI、Happy、Kanna | 不做：iOS 听写已可用；需要中转；属于已拒绝的多模型 |

### 第 1 轮做法

- 新建对话框里，在选好工作目录后列出这个目录最近 20 段对话（Claude Code 的标题、最后一句回复、多久以前），没有提问的空对话不显示。如果某段对话正在某个会话里打开（有 hooks 时才知道），会标注出来。
- 选一段对话后按钮变为「接着聊」，启动 `claude --resume <id>`；勾选「分叉」就加上 `--fork-session`，原来那段对话不受影响。
- 只接受这个目录 transcript 里真实存在的 UUID，所以 id 不会被拼进 shell 命令造成注入。摘要按文件大小和修改时间缓存，每段只读末尾 512KB。

**成本与风险**：只改 server 和 web；新增一个只读、需登录的 GET 接口，只返回标题和最后一句话；不加依赖，不改 Mac App。

### 第 2 轮做法

- 「± 改动」页在没提交的改动下面列出当前分支最近 30 个提交（短号、标题、多久以前）。有上游分支时，标出哪些还没推送，以及落后上游几个提交。
- 点一个提交可以展开它的说明、文件统计和 diff。
- 提交号只接受十六进制，并且要先确认它确实是一个提交，所以不会被 git 当作参数或 `HEAD~1` 这类表达式。所有 git 调用额外关掉 `log.showSignature`：仓库配置的 `gpg.program` 因此不会被执行。

### 第 3 轮做法

- 「用量」页最上面加「服务器」一栏：可用内存、CPU 负载（按核数），有交换区时显示用了多少。下面列出每个 tmux 会话整棵进程树占的内存，以及 Claude Hub 自己占多少。页面在前台时每 5 秒刷新。
- 新建对话框显示服务器还剩多少内存、每个会话平均占多少。剩余不到 15%（或不到 500MB）时标红，提示先关掉不用的会话。
- 只读 Linux 的 `/proc`，不调用任何外部程序；其他系统上这一栏不显示。

**结论**：做（三轮分别提交）。

## 2026-11-23 · 输入栏补全：@文件、/命令

**需求原话**：继续优化（由 Claude 判断做什么）。

**问题**：输入栏现在是默认的输入方式，但它是网页里的普通输入框，Claude Code 自己输入框里的 `@` 文件补全和 `/` 命令补全都没有了。用户只能手打路径，自定义命令和 skill 也想不起名字。

**做法**：
- 输入 `@` 后弹出会话项目里的文件和文件夹：git 仓库用 `git ls-files`，所以遵守 .gitignore；不是仓库就遍历目录，跳过隐藏目录和 node_modules，限制数量和深度，结果缓存 10 秒。匹配顺序是路径前缀、文件名前缀、包含、子序列，最多 30 条。选文件夹会继续列出它里面的东西。
- 输入框以 `/` 开头时弹出命令：内置常用命令，加上项目和用户自己的 `.claude/commands/**/*.md`（子目录记成 `dir:name`）、`.claude/skills/*/SKILL.md`，描述取自 front matter。
- ↑↓ 选择，Tab 填入，回车：在命令上直接执行，在文件上只填入。Esc 关闭弹窗。手机上点一下填入。输入法选字时不触发。

**成本与风险**：只改 server 和 web。新增两个只读 GET 接口，需要登录：返回的是文件名和命令名，不返回文件内容；范围和「📁 文件」一样，限定在会话工作目录。不加依赖。

**结论**：做。

## 2026-11-23 · 竞品第三轮：对话阅读视图、git 改动面板、只读文件 / Markdown 查看

**需求原话**：继续下面要做的（上一轮评审里排到「下一轮」的几项，由 Claude 判断取舍）。

**理解与价值**：在手机上看 Claude 做了什么很难——终端要来回滚，表格和长回复会被折行打乱。官方 App、CloudCLI、Codeman 都有「对话气泡视图 + 改动 diff + 文件查看」。对所有用户都有用，尤其手机端。

**做法**：
- 终端标题栏加「📖 查看」，打开右侧只读面板（手机上全屏），三个页签：
  - 对话：从 transcript（hooks 报告的路径，没有 hooks 就用该目录最新的 .jsonl）读最后 2MB、最多 300 条；连续的助手记录合并，工具调用折叠成一行（名字 + 关键参数，出错标红），工具结果和 Claude Code 自己的包装消息不显示。Claude 工作时每 4 秒刷新。
  - 改动：会话目录所在 git 仓库的 `git status` 和单文件 diff（相对 HEAD，未跟踪文件显示为全部新增）。
  - 文件：浏览会话工作目录，文本文件带行号，Markdown 渲染预览。
- 终端里的文件路径 ⌘ 点击（手机上轻点）直接在文件页签打开。
- Markdown 自己写了个小渲染器，生成 React 元素而不是 HTML 字符串，所以不存在 HTML 注入；只有 http(s) 链接能点。不加依赖。

**成本与风险**：只改 server 和 web，不改 Mac App。全部是 GET、要登录，安全模型不变。
- 文件读取限制在会话工作目录内：先解析符号链接再检查路径，指向目录外的链接、`..` 和绝对路径都会被拒绝。只显示前 512KB，二进制文件不显示内容，目录最多列 500 项。
- diff 只接受 `git status` 报出来的路径，所以用户输入不会被 git 当成参数（例如 `--output=`）。git 带着 `GIT_OPTIONAL_LOCKS=0` 运行，不会和 Claude 正在做的提交抢锁；同时关闭 fsmonitor、外部 diff 和 textconv，仓库配置不能借此运行程序；8 秒超时，输出上限 256KB。
- 能登录的人本来就有完整终端，所以这些只读接口没有扩大权限。

**结论**：做。下一项「额度用完到点自动续跑」单独评审、单独提交。

## 2026-11-22 · 输入不丝滑：输入栏默认开、发送更可靠、Esc 立刻生效、xterm 6

**需求原话**：感觉这个输入框还是很不丝滑很不好用，Mac 输入的时候也有点不顺畅……能不能好好优化下输入相关的，去 GitHub 看看。

**实测原因**：
- Mac 到服务器往返约 80ms（Tailscale 直连）。直接在终端里打字时，每个字都要等服务器回显才显示，所以发黏；中文输入法的候选和上屏也受这个延迟影响。服务器本地回显只要约 10ms，Mac App 转发两端也都已经开了 TCP_NODELAY，所以延迟就是网络往返本身。
- tmux 的 `escape-time` 是默认的 500ms，实测按 Esc 后 565ms 才生效。
- 调研参考：Codeman 的 xterm-zerolag-input（本地缓冲输入）；xterm.js 6.0 修了部分输入法重复出字（#5024）；Claude Code 已知问题——回车比文字先到会发空（#28137），括号粘贴里的斜杠命令不会执行（#85654）。候选框位置漂移是 Claude Code 自己画光标导致的，在 xterm 这边修不掉。

**做法**（用户已选 ①②③④）：
1. 输入栏在电脑和手机上都默认打开（终端标题栏有「⌨ 输入栏」开关，偏好存在本机浏览器）。字在本地输入框里打，不等回显，输入法走系统原生。Mac 上回车发送、Shift+回车换行；输入法正在选字时按回车不会误发（同时检查 isComposing、keyCode 229，以及 compositionend 后 80ms 内的回车）。输入框为空时，↑↓、Tab、⇧Tab、回车直接交给 Claude（用来翻菜单、确认）。Esc 和 Ctrl-C 随时可以打断。输入框随内容自动长高。截图可以直接粘贴到输入栏。
2. 发送改由服务器完成（`POST /api/sessions/{name}/send`）：先输入文字，读屏确认文字已经出现在 Claude 的输入框里（最多等 1.5s），再按回车。单行文字逐字输入，所以 `/compact` 这类命令照常执行；多行用括号粘贴，换行不会被当成提交。多条消息排队发送，不会串在一起。
3. 启动时和新建会话后，如果 tmux 的 escape-time 还是默认的 500，就改成 10ms。只改运行中的 tmux，不写任何配置文件；用户自己设过的值不动；`-tmux-escape-time=-1` 可以关掉这个行为。
4. @xterm/xterm 从 5.5 升到 6.0（插件同步升级）。iOS 中文标点的修复（#5614）还没合并，暂时不打补丁。

**成本与风险**：改 server 和 web，不改 Mac App，不加新依赖（只升级 xterm 版本）。escape-time 会影响同一个 tmux server 里的其他会话（Esc 和 Alt 组合键更快响应），属于常见推荐设置。

**结论**：**做**。

## 2026-11-22 · 搜狗输入法在 ✎ 输入框中间插字会删掉前面的字

**需求原话**：手机能打字了，但是如果在简体字中间打字，反而会删除前面的文字。（补充：搜狗，✎ 输入框；别的网页正常，只有 Claude Hub 会）

**原因（推断）**：发送后用 `textarea.value = ""` 清空输入框。脚本直接改 value 不经过编辑流程，第三方键盘感知不到，仍以为框里是上一条已发送的文字；之后再编辑，它按旧的上下文去「删拼音」，删掉了别的字。别的网页不会用脚本清空输入框，所以正常。没有真机和搜狗输入法，无法直接复现。

**成本与风险**：只改 web 一个组件。

**结论**：**修（bug）**：改为聚焦 → 全选 → `execCommand("delete")` 清空，走正常编辑流程，键盘能感知；不支持时再退回直接赋值。e2e 断言清空产生的是 delete 类 input 事件。请用户真机确认；如果仍复现，下一步排查终端输出导致的页面频繁变动。
